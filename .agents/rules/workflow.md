# How We Work Together
- I am a non-programmer directing this build. Explain technical decisions
  in plain language when they matter, but don't over-explain routine code.
- Work in small, named phases. Do not start the next phase until I confirm
  the current one works.
- Before writing code for a new phase, first summarize your plan and any
  assumptions or open questions, and wait for my confirmation.
- Never change a formula in docs/pricing-rules.md, a table/field in
  docs/data-model.md, or a permission rule in docs/permissions.md without
  explicitly asking me first and explaining why.
- After each phase works, tell me the exact commands to test it myself
  before we move on.
- If something in docs/ is ambiguous or contradicts something else, stop
  and ask me — do not guess and proceed.
